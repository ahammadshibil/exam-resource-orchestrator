# Contributing

Bug reports, focused fixes and source-quality improvements are welcome.

1. Open an issue describing the problem or proposed behavior for substantial changes.
2. Fork the repository and create a branch for your change.
3. Keep changes focused and add meaningful tests for behavior changes.
4. Run the relevant checks listed in the README and open a pull request explaining the result.

Use synthetic learner data in tests and examples. Never commit credentials, private learner files, chat history or progress databases. Report suspected exposed credentials privately to the repository owner rather than posting the secret in an issue.

For catalog changes, include provenance and retrieval dates, preserve attribution, and distinguish verified titles from URL-derived labels. Do not add copied teaching content without appropriate permission. Keep access restrictions explicit and do not equate clicks or resource completion with mastery.

Run the catalog sync script after editing the root metadata snapshots. Preserve upstream notices when modifying LearnHarness, and describe upstream changes separately in the pull request.

Contributions to project code are made under AGPL-3.0-only. Third-party metadata retains its documented terms.
